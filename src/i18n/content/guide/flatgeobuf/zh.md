FlatGeobuf（`.fgb`）是为「快速读取、流式处理、按空间范围过滤」设计的二进制矢量格式。它基于 FlatBuffers，常被用作 Web 地图和大型数据集的传输格式。

## 文件结构

1. **文件头**：magic 标识、版本、要素数量、图层 schema（字段名与类型）。
2. **空间索引**：默认打包 R-tree，记录每个要素的包围盒。
3. **要素数据**：逐条存储几何与属性，可以顺序读取。

因为索引在前，客户端可以先读索引，判断哪些要素落在当前视野，再只下载命中的部分。这对 Web 地图很有价值：不必先下载整个文件。

## 特点

- **没有 10 字符字段名限制**，字段类型更完整。
- **单文件、单图层**，多图层需要多个文件。
- **支持流式处理**，适合大数据和按需加载。
- **文件比 GeoJSON 小**，解析也更快。
- **有空间索引**，范围查询不需要全表扫描。

## 限制

- **不可读**：不能用文本编辑器打开，出问题必须用专门工具。
- **单图层**：不能像 GeoPackage 一样在一个文件里放多个图层。
- **写入后修改不灵活**：通常整文件重写，不适合频繁编辑。
- **生态比 Shapefile / GeoPackage 小**，老旧软件可能不支持。

## 适用场景

| 场景 | 是否适合 |
|---|---|
| Web 地图按视野加载 | 适合 |
| 几十万到上百万要素的只读数据 | 适合 |
| 需要多图层管理 | 不适合，用 GeoPackage |
| 需要人工检查文件内容 | 不适合，用 GeoJSON |
| 传统 GIS 交付 | 先确认对方支持 |

## 转换时注意

FlatGeobuf 转 GeoJSON 会展开为普通要素集合，属性保留；反过来，多图层或复杂样式无法写入。需要互转时用 [矢量格式转换](/zh/tools/format-convert/)；与 GeoPackage 的对比见 [GeoPackage](/zh/guide/geopackage/)。
