CSV 和 TSV 是最普通的表格文本，也是地理数据交付中最容易出问题的格式：没有坐标系声明、没有几何类型，一切都依赖列名和约定。

## 两种组织方式

**经纬度两列**，适合点数据：

```csv
name,lng,lat,category
天安门,116.3974,39.9088,landmark
故宫,116.3970,39.9163,landmark
```

**一列 WKT 几何 + 属性列**，适合点线面混存：

```csv
name,geom,area_m2
示例范围,"POLYGON ((116.39 39.90, 116.41 39.90, 116.41 39.92, 116.39 39.90))",482000
示例道路,"LINESTRING (116.39 39.90, 116.40 39.91)",0
```

只要出现线或面，就必须用 WKT 列，否则几何会被压扁成点。

## TSV

TSV 用制表符分隔，规则与 CSV 相同。优势是地址、名称里可以出现逗号而不必加引号：

```tsv
name	lng	lat
天安门	116.3974	39.9088
故宫	116.3970	39.9163
```

代价是制表符不能出现在字段内，复制粘贴时容易被空格替换。

## 五个常见陷阱

1. **编码**：中文 CSV 常见 UTF-8、UTF-8 BOM、GBK。没有 BOM 的 UTF-8 在 Excel 里可能乱码。
2. **逗号冲突**：字段含逗号必须用双引号包住；字段内的双引号写成两个。
3. **经纬度顺序**：表头写 `lng,lat` 最清晰；只写 `x,y` 时要确认 x 是经度还是投影东坐标。
4. **小数分隔符**：`116,3974` 会被当成两列，转换前统一为句点。
5. **空行与多行表头**：都会让列映射失败。

## 与其他格式的关系

CSV / TSV 只承载数值和文本，几何要么靠两列经纬度，要么靠 WKT。需要把表格转成矢量数据时，用 [矢量格式转换](/zh/tools/format-convert/)；需要批量计算坐标或距离时，用相应工具页下方的批量面板。更多格式见 [总览](/zh/guide/vector-formats/)。
