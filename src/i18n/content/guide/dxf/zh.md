DXF（Drawing Exchange Format）是 AutoCAD 的交换格式，CAD 与 GIS 之间传数据经常用它。ASCII 版本是纯文本，内容由「组码 + 值」成对排列。

它出现的原因很实际：DWG 是 AutoCAD 的原生二进制格式，结构不公开，别的软件很难直接读写；DXF 把同样的图形内容用公开结构写出来，于是成了事实上的交换标准。代价是这个格式面向制图，不面向地理数据。属性、坐标系、拓扑这些 GIS 概念，在格式里找不到对应位置。

## 最小可用示例

```text
0
SECTION
2
ENTITIES
0
POINT
8
0
10
116.3974
20
39.9088
0
LINE
8
0
10
116.39
20
39.90
11
116.40
21
39.91
0
ENDSEC
0
EOF
```

- `0/SECTION` + `2/ENTITIES` 进入实体段。
- `0/POINT` 开始点实体，`8` 是图层，`10/20` 是 X/Y。
- `0/LINE` 的起点是 `10/20`，终点是 `11/21`。
- `0/ENDSEC`、`0/EOF` 结束文件。

常见实体还有 `LWPOLYLINE`（轻量多段线）、`CIRCLE`、`ARC`、`TEXT`、`INSERT`（块参照）。

从读取端看，最小的文件可以只有一个 `ENTITIES` 段加一个实体，再加 `EOF`。实际图纸几乎都会带上 `HEADER` 和 `TABLES`，单位、范围、图层定义都放在那里。ASCII 版本里组码和值各占一行，顺序固定：先组码，后值。DXF 另外还有二进制版本，更紧凑，但开头带二进制标记，不能当文本解析。

## 结构与字段说明

| 段 | 内容 | 是否必需 | 常见取值 |
|---|---|---|---|
| `HEADER` | 图形变量：单位、范围、版本 | 通常有 | `$INSUNITS`、`$EXTMIN` |
| `TABLES` | 图层、线型、文字样式定义 | 通常有 | `LAYER` 表 |
| `BLOCKS` | 块定义 | 有块参照时 | `BLOCK` |
| `ENTITIES` | 图形实体 | 必需 | `POINT`、`LINE`、`LWPOLYLINE` |
| `OBJECTS` | 非图形对象 | 可选 | 字典、扩展数据 |

常用组码：

| 组码 | 含义 | 常见取值 |
|---|---|---|
| `0` | 段或实体类型 | `SECTION`、`POINT`、`EOF` |
| `2` | 名称 | `ENTITIES`、图层名 |
| `8` | 图层 | `0`、`道路` |
| `10` / `20` / `30` | 起点或点的 X/Y/Z | 数值 |
| `11` / `21` / `31` | 终点 X/Y/Z | 数值 |
| `42` | 凸度，描述圆弧段 | `0` 表示直线段 |
| `62` | 颜色号 | 颜色索引 |
| `70` | 标志或计数 | 整数 |

图层不是实体自带的属性，而是在 `TABLES` 段的 `LAYER` 表里统一定义，实体通过组码 `8` 引用图层名。表里记名称、颜色、线型等设置，实体只存名字。这意味着直接把 `ENTITIES` 段截出来会丢掉图层定义，转换后可能只剩默认图层。

实体靠组码区分：`POINT` 只有一个坐标，`LINE` 有起点和终点，`LWPOLYLINE` 存一串顶点，并用凸度描述圆弧段。`CIRCLE` 和 `ARC` 用圆心加半径表达，不是折线。`INSERT` 引用 `BLOCKS` 里的块定义，还可能带缩放、旋转和阵列参数。

DXF 没有字段这个概念。所有信息要么是几何，要么是图层名、颜色、文字内容这类固定属性，没有「名称」「面积」「编号」这类用户自定义字段，也没有 NULL。要在 GIS 里按属性查询，只能另建属性表。

## 坐标与单位

DXF **没有强制的坐标系声明**。坐标可能是经纬度，也可能是以米为单位的工程坐标。判断方法只有两个：问数据提供方，或者看数值范围落不落在经纬度区间。

`HEADER` 里的 `$INSUNITS` 只说明绘图单位是米、毫米还是英寸，不说明这些坐标在地球上的位置。测量和规划图纸常用本地平面坐标，原点可能是工地一角，数值范围和经纬度完全不是一回事。少数图纸会附带说明文件或世界文件，但这不是 DXF 自身的能力。

看数值量级也是个办法：经纬度一般在三位数和两位数范围内，工程坐标常见几十万到几百万。也可以用已知地物反推，但这需要外部参照，光靠文件本身做不到。

## 已知限制

- **圆弧和样条会被离散**：转成 GeoJSON 或 Shapefile 后通常变成折线，点数取决于导出设置。
- **文字与块属性不会自动成为字段**：`TEXT`、`MTEXT`、`ATTRIB` 需要单独提取。
- **图层与样式丢失**：目标格式如果没有图层概念，只能退化成属性或直接丢弃。
- **二进制 DXF** 不能按文本解析，需要先另存为 ASCII。

除此之外，DXF 没有拓扑，没有坐标系，也没有空值语义。同一图层里的实体可以混合点、线、面和文字，制图里这很正常，到了 GIS 里就必须拆成不同图层或不同几何类型。

## 常见错误与陷阱

**把二进制 DXF 当文本读**：现象是开头一片乱码，解析器在第一个组码处就失败；原因是二进制版本用固定标记开头，内容是紧凑编码；后果是只能回 CAD 里另存为 ASCII 再处理。

**把 CAD 坐标直接当经纬度用**：现象是数据落在非洲西侧的海里，或者整体飞出地图范围；原因是 DXF 不声明坐标系，工程坐标的量级和经纬度完全不同；后果是叠不上底图，得先确定原点与投影，再做坐标转换。

**忽略多段线的凸度**：现象是带圆弧的边界变成折线，面积和长度都出现偏差；原因是 `LWPOLYLINE` 用组码 `42` 描述弧段，简单解析器只读顶点；后果是几何形状改变，而且这种损失通常不可逆。

**没有炸开块参照**：现象是只看到插入点，块内部的几何全部缺失；原因是 `INSERT` 只是引用，几何存放在 `BLOCKS` 段；后果是要素数量不对，得先炸开或递归解析块定义。

**把所有实体都留在图层 `0`**：现象是转换后没法按类别筛选，全部要素混在一起；原因是绘图时没分层，或者导出时被强制合并到默认图层；后果是分类信息丢失，只能按几何或文字重新推断。

## 与相邻格式对比

| 维度 | DXF | GeoJSON | Shapefile | GeoPackage |
|---|---|---|---|---|
| 属性模型 | 无自定义字段 | 任意 JSON 属性 | DBF 字段，名称 10 字符 | 完整表结构 |
| 坐标系 | 不声明 | 约定 WGS84 | 可选 `.prj` | 每图层声明 SRS |
| 几何表达 | 实体集合，含圆弧与块 | 点线面和集合 | 单几何类型 | 多类型，WKB |
| 图层 | 有图层，无字段 | 无 | 无 | 多图层 |
| 体积 | 文本较大，二进制较小 | 大 | 中等 | 中等偏大 |
| 可读性 | ASCII 可读 | 纯文本 | 部分可读 | 需 SQLite |
| 典型用途 | 制图与设计 | Web 传输 | 传统 GIS 交付 | 数据管理与交付 |

### 适用场景

| 场景 | 建议 |
|---|---|
| 从 CAD 提取地块边界 | DXF → GeoJSON / GeoPackage |
| 保留图纸继续编辑 | 继续用 DXF |
| 需要属性表 | 先把文字和块属性整理成 CSV，再与几何关联 |
| 需要坐标系 | 向提供方确认，或按已知工程坐标转换 |

## 转换与工具入口

DXF 转 GIS 格式，通常只保留几何和图层名：文字、标注、填充图案会被丢弃或退化成点。业务上需要文字内容的话，最好在转换前按位置把文字和几何关联起来，另导一份属性表。

转换流程一般三步：确认单位与坐标性质，把工程坐标转到目标坐标系，再按几何类型拆分实体。圆弧和样条在第一步就得定离散精度，太粗会失真，太细会让要素数量暴涨。

需要互转时用 [矢量格式转换](/zh/tools/format-convert/)；投影坐标先经 [投影坐标转换](/zh/tools/epsg-convert/) 处理到 WGS84。其他制图格式见 [GMT](/zh/guide/gmt/) 与 [MIF/MID](/zh/guide/mif-mid/)，字段与几何结构的参考见 [GeoJSON](/zh/guide/geojson/)。

## 示例数据与解析脚本

[sample.dxf](/examples/data/sample.dxf) 是 ASCII 版本的最小示例，包含一个 `POINT`、一条 `LINE` 和一条 `LWPOLYLINE`，用文本编辑器就能看清组码结构。

[dxf_parser.py](/examples/python/dxf_parser.py) 基于 ezdxf，把 `POINT` 转成点、`LINE` 转成线、`LWPOLYLINE` 转成线或闭合面，圆和圆弧按固定段数离散，图层名作为属性保留，其余实体跳过。

```text
python dxf_parser.py sample.dxf -o out.geojson
```

脚本不读坐标系，也不做重投影。输出的坐标量级很大，说明图纸用的是工程坐标；某个图层缺失，先查实体是不是在块参照里，是的话需要炸开。
