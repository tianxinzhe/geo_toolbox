Shapefile 是 GIS 里用得最广的矢量格式，1990 年代由 Esri 定义。它的实际形态是一组同名文件，并非单个文件。别人说「打不开」，多数时候是缺了其中某一个。

规范文本出自 Esri 的技术白皮书，之后基本没再扩展。它之所以流行，是因为出现得早、实现简单、几乎什么软件都能读写，跟设计是否先进关系不大。流行也把历史包袱一并留了下来：字段名长度、几何类型、文件大小都写死在格式定义里，改不了。

## 最小可用示例

| 文件 | 作用 | 是否必需 |
|---|---|---|
| `.shp` | 几何坐标 | 必需 |
| `.shx` | 几何索引 | 必需 |
| `.dbf` | 属性表（dBASE） | 必需 |
| `.prj` | 坐标系声明（WKT） | 建议 |
| `.cpg` | 属性表编码 | 建议 |

少了 `.shx`，一些软件建不了索引；少了 `.prj`，坐标系无从判断；少了 `.cpg`，中文属性可能变成乱码。

交付时把同名文件打成一个 ZIP，`.shp`、`.shx`、`.dbf` 三个必须有，`.prj` 和 `.cpg` 尽量一起带上。只发一个 `.shp`，是最常犯的错。

```text
sample.shp
sample.shx
sample.dbf
sample.prj
sample.cpg
```

桌面 GIS 打开时一般只要选中 `.shp`，同目录的其他同名文件会自动加载。方便，也容易出事：复制、上传、压缩的时候只把 `.shp` 带走了，几何还在，属性却没了。

另外还可能有 `.sbn` / `.sbx`（Esri 的空间索引）、`.qix`（GDAL、MapServer 用的索引）、`.shp.xml`（元数据）。这几个都不是必需项，缺了顶多影响读取速度或元数据，几何与属性不受影响。

## 结构与字段说明

`.shp` 以一个固定长度的文件头开头，记着文件长度、版本、几何类型和整体包围盒，后面按顺序排着每条几何记录。`.shx` 则给每条记录存一份固定长度的偏移和长度，作用类似目录，软件不用顺序扫描就能定位要素。这两个文件必须同步，只替换其中一个，记录就会错位。

`.dbf` 是一张 dBASE 表。开头是字段定义，每个字段带名称、类型、长度和小数位；后面是定长记录，补不齐的地方用空格填上。字段名最多 10 个字符，类型也就字符、数值、浮点、日期、逻辑、备注这么几种，数组、嵌套结构和 JSON 都放不进去。

| 位置 | 内容 | 说明 |
|---|---|---|
| `.shp` 文件头 | 版本、几何类型、包围盒 | 几何类型在文件级别固定 |
| `.shp` 记录 | 记录号、内容长度、坐标 | 顺序存储 |
| `.shx` 记录 | 偏移、内容长度 | 与 `.shp` 记录一一对应 |
| `.dbf` 字段定义 | 名称、类型、长度、小数位 | 名称最多 10 字符 |
| `.dbf` 记录 | 属性值 | 定长，补空格 |
| `.prj` | 坐标系 WKT | 单行文本 |

常见的 DBF 字段类型：

| 类型 | 含义 | 常见取值 |
|---|---|---|
| `C` | 字符 | 名称、分类、编码 |
| `N` | 数值 | 面积、人口、编号 |
| `F` | 浮点 | 长度、比例 |
| `D` | 日期 | `YYYYMMDD` |
| `L` | 逻辑 | `T` / `F` |

这套类型是从 dBASE 继承来的，不是按 GIS 的需求设计的。日期不带时区，逻辑值表示不了「未知」，数值也没有统一的精度声明，读取时只能按字段长度去猜。空值同样不是真正的 NULL，而是空白或 0，「没有值」和「值为空字符串」很难分开。

历史限制：

- **一个图层只能一种几何类型**：点、线、面必须拆成多个 Shapefile。
- **字段名最多 10 个字符**，中文或长英文名会被截断、重命名。
- **单文件不超过 2GB**，超出必须分片。
- **字段数量和文本长度有上限**，长文本会被截断。
- **不支持 NULL 与复杂类型**，日期、布尔等类型表达有限。

这些限制写在格式定义本身里，怪不到某个软件头上。转换工具可以把数据搬到新格式，但已经截断的字段名、丢掉过的空值，不会自己长回来。

## 常见错误与陷阱

**只发 `.shp` 一个文件**：对方打开后发现没有属性表，或者软件直接报错；问题出在 `.dbf` 与 `.shx` 没一起发；这份数据基本用不了，只能重新交付。

**中文属性显示为乱码**：字段值成了问号、方块或陌生字符；根源是 `.dbf` 按代码页存字节，`.cpg` 要么缺失，要么声明的编码和实际内容对不上；属性读不出来，筛选、关联、导出接连出错，而且光看文件本身一般判断不出原始编码。

**字段名变成 `NAME_1`、`FIELD_2`**：原来写的中文名或长英文名被替换了；DBF 字段名限 10 个字符，早期实现还只认 ASCII；属性与含义脱钩，跟外部表关联时得重新建映射。

**点、线、面混在一个图层里**：导入后只出来一部分要素，或者多出一堆空几何；同一个 `.shp` 的有效几何类型必须一致，规范虽允许 Null 记录，但多数软件不会替你拆分；结果是数据不完整，得按几何类型拆成多个文件。

**打开后位置偏到几百万米之外**：要素跑到底图范围外，比例尺也对不上；不是 `.prj` 缺失或写错，就是这份数据本来就是工程坐标；跟其他数据叠不上，只能重新确认坐标系再做投影。

**写到一半失败或文件损坏**：某个要素之后的数据整段消失；`.shp` 用 32 位偏移记录位置，单个文件顶到 2 GB 就写不下了；超出的部分只能按范围或要素数分片，最后到目标格式里合并。

## 与相邻格式对比

| 维度 | Shapefile | GeoPackage | FlatGeobuf | GeoJSON |
|---|---|---|---|---|
| 文件构成 | 多个同名文件 | 单个 SQLite 文件 | 单个文件 | 单个文本文件 |
| 图层与几何 | 单图层、单几何类型 | 多图层、多类型 | 单图层 | 单集合、多类型 |
| 字段 | 名称 10 字符、类型少 | 取决于 SQLite 表结构 | 类型较完整 | 由 JSON 决定 |
| 坐标系 | 可选 `.prj` | 每个图层声明 SRS | 文件头可选声明 | 约定 WGS84 |
| 空间索引 | 依赖附带的索引文件 | R-tree 表 | 打包 Hilbert R-tree | 无 |
| 体积 | 中等 | 中等偏大 | 较小 | 最大 |
| 流式读取 | 不支持 | 不支持 | 支持 | 不支持 |

什么时候仍然要用它：

- 对接只认 Shapefile 的传统 GIS 或行业流程。
- 需要被老旧软件读取。
- 数据量不大、字段简单。

有得选的话，GeoPackage 能放多图层、字段名不受 10 字符限制、类型系统也更完整，正逐步接替 Shapefile 成为交付格式。

## 转换与工具入口

从 Shapefile 转 GeoJSON 或 GeoPackage，被截断的字段名、受过的几何类型限制都不会自动还原；多图层往往要拆成几个文件，反过来转则要把多个图层分别导出。

动手前先确认三件事：文件齐不齐、`.prj` 里声明的坐标系是不是你要的、目标格式能不能装下现有字段名和类型。转到 GeoPackage 或 FlatGeobuf 后，字段名不再受 10 字符限制，可已经被截断的名字还是原样；反过来转的时候，长字段名会被再截一次，最好提前换成短名。

需要互转时用 [矢量格式转换](/zh/tools/format-convert/)；坐标系不确定时先用 [投影坐标转换](/zh/tools/epsg-convert/) 处理到 WGS84。二进制格式对比见 [GeoPackage](/zh/guide/geopackage/) 与 [FlatGeobuf](/zh/guide/flatgeobuf/)，文本结构和字段细节可参考 [GeoJSON](/zh/guide/geojson/)。

## 示例数据与解析脚本

[sample-shapefile.zip](/examples/data/sample-shapefile.zip) 是打包好的最小示例，五个文件齐全（`.shp`、`.shx`、`.dbf`、`.prj`、`.cpg`），拿来验证完整读取流程正合适。

[shapefile_parser.py](/examples/python/shapefile_parser.py) 基于 pyshp，能读 `.shp` 或 ZIP，把每个要素转成 GeoJSON；字段名保持原样，空几何会跳过。脚本不读 `.prj`，也不做重投影，坐标按文件里的原值输出。

```text
python shapefile_parser.py sample.shp -o out.geojson
```

输出里属性为空，先看 `.dbf` 是不是和 `.shp` 放在一起；坐标量级明显偏大，说明数据是投影坐标，得先转成经纬度。
