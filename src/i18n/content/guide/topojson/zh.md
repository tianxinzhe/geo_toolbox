TopoJSON 可以看成 GeoJSON 的压缩版兼拓扑版。它同样是 JSON 文本，但不把每个多边形的完整轮廓都存一遍，而是把共享边界抽成 `arcs`，几何只引用弧段编号。

多出这一层间接引用，换来的不只是文件更小。相邻行政区、地块、流域的公共边在文件里只存一份，改一条弧，两侧边界一起变，不会冒出「你的边界和我的边界差几厘米」那种缝。代价也明确：任何工具都得先把它还原成 GeoJSON，才能画到地图上。

## 为什么需要它

行政区划、地块、流域这类数据，相邻多边形之间共享着大量边界。同一段公共边，GeoJSON 要存两遍甚至更多遍，TopoJSON 只存一次。再加上整数化和共享字符串，文件能缩到原来的几分之一。

共享边越多，这种收益越明显。省界、县界这类层层嵌套的数据里，一条边界可能被三四个面同时引用。反过来，散点、独立地块几乎不共享边界，套上 TopoJSON 只是多一层转换，体积上占不到便宜。

## 最小可用示例：基本结构

```json
{
  "type": "Topology",
  "transform": { "scale": [0.0001, 0.0001], "translate": [116.3, 39.8] },
  "objects": {
    "districts": {
      "type": "GeometryCollection",
      "geometries": [
        { "type": "Polygon", "arcs": [[0]], "properties": { "name": "A" } },
        { "type": "Polygon", "arcs": [[1]], "properties": { "name": "B" } }
      ]
    }
  },
  "arcs": [
    [[0, 0], [1000, 0], [1000, 1000], [0, 0]],
    [[1000, 0], [2000, 0], [2000, 1000], [1000, 0]]
  ]
}
```

- `objects` 相当于图层容器，可以放多个几何集合。
- `arcs` 是去重后的路径，坐标是量化后的整数，按 `transform` 还原。
- `transform.scale` 与 `translate` 决定还原后的真实坐标。
- 负的弧段编号表示反向引用同一条弧。

上面这份示例为了看清结构，坐标都写成了完整整数。真实文件不是这样：每段弧只有第一个点是绝对值，后面每个点存的是相对前一个点的差值。站点提供的 `sample.topojson` 就是这么写的，`arcs` 的第二项是 `[83, -53]`，还原时得先加上前一点，别把它当成新坐标。

## 结构与字段说明

| 字段 | 作用 | 是否必需 | 常见取值 |
|---|---|---|---|
| `type` | 标识顶层对象类型 | 必需 | `"Topology"` |
| `objects` | 图层名到几何对象的映射 | 必需 | `districts`、`stations` |
| `arcs` | 去重后的弧段集合 | 必需（可为空数组） | 整数坐标数组 |
| `transform` | 量化参数 | 可选 | `scale`、`translate` |
| `bbox` | 包围盒 | 可选 | 四个或六个数字 |
| `properties` | 属性，挂在几何对象上 | 可选 | 与 GeoJSON 相同 |
| 弧段索引 | 引用 `arcs` 的编号 | 几何内部 | 非负整数或负数 |

有几条规则容易踩坑。`objects` 是对象，不是数组，键名即图层名，解析时一般按顺序取值。`GeometryCollection` 允许嵌套，里面的子几何照样通过 `arcs` 引用弧段。线状几何的 `arcs` 是一串编号；面状几何的 `arcs` 是「环的数组」，每个环又是一串编号，第一个环是外环，其余是洞。点比较特殊，没有弧段，`coordinates` 直接写量化后的绝对整数。

属性还是在 `properties` 里，结构和 GeoJSON 一样，还原时一般不会丢。真正容易丢的是对象名和量化参数，得另外记下来。

负数索引是 TopoJSON 独有的。编号 `i` 表示顺着走第 `i` 条弧，`~i`（也就是 `-i-1`）表示倒着走同一条弧。有了它，两个相邻面能共用一条弧，不用为其中一个专门反向复制一份。正负号读错，外环就变成内环，面要么渲染成洞，要么直接不见。

## 量化与精度

TopoJSON 习惯用整数坐标来压浮点数。`scale` 是量化网格的边长：调大，网格变粗，整数变小，文件也跟着小，代价是坐标偏移更大；调小，精度上去，体积就下不来。厘米级或测量级的数据，量化误差可能吃不消，动手前先想清楚精度要求。

还原就一个式子：真实坐标 = `translate` + `scale` × 整数值。`scale` 取 0.0001 度时，赤道附近网格边长约 11 米，量化误差大致也在这个量级。省界、市界用这个精度没问题，地籍和管线就不行。量化还有个副作用：落进同一格的相邻点会被合并，很短的边还原之后可能消失，变成退化环。

拓扑还有个实际好处：简化时不会裂开缝隙。按拓扑简化，共享弧段只处理一次，两侧多边形仍然对得上；要是把两份 GeoJSON 各自简化，公共边就会错位，出现头发丝一样的缝或者重叠。边界数据常常先转成 TopoJSON、简化完再转回去，原因就在这里。

## 常见错误与陷阱

### 把 TopoJSON 直接交给地图库

**现象**：地图一片空白，控制台提示几何类型未知，或者只画出一个点。

**原因**：地图库是按 GeoJSON 读的，要的是顶层 `FeatureCollection`，文件顶层偏偏是 `Topology`，几何还藏在 `objects` 里，引用着 `arcs`。

**后果**：不是直接报错，就是读出一个空集合。得先用 `topojson-client` 的 `feature()` 还原，或者让转换工具先转回 GeoJSON。

### 手工修改 arcs 坐标

**现象**：原本严丝合缝的两块区域裂开了，或者边界互相穿插。

**原因**：同一条弧会被多个几何引用，改一处，引用它的面全跟着变；再加上差值编码，动一个点，后面所有点都受影响。

**后果**：拓扑被破坏，还很难查出是哪一块改坏的。要编辑，就回 GIS 软件里改几何，再重新生成 TopoJSON。

### 量化过粗

**现象**：边界明显出现锯齿，小岛不见了，窄面缩成一条线。

**原因**：`scale` 定得太大，网格过粗，相邻点被并进同一个格子。

**后果**：精度损失不可逆。拓扑本身还是一致的，毕竟两侧共用同一批点，但形状已经走样，再转一次也救不回来。

### 弧段索引方向写错

**现象**：某个面渲染出来是空心的，或者面积算出来是负数。

**原因**：负数索引是反向遍历，`-1` 说的是第 0 条弧倒着走；一旦当成「第 1 条弧」，绕向就整个反了。

**后果**：外环、内环判断颠倒，面被填成洞，或者干脆被渲染器丢掉。

### 只取 objects 的第一个键

**现象**：转完只剩一个图层，其他对象都没了。

**原因**：`objects` 是个映射，一个文件里可以同时塞行政区、道路、水系好几个对象。

**后果**：数据不完整。转换前先数一下对象有几个，需要的话逐个展开再合并。

## 与相邻格式对比

| 格式 | 体积 | 拓扑 | 可读性 | 兼容性 |
|---|---|---|---|---|
| TopoJSON | 小，共享边越多越明显 | 有，共享弧段 | 中，需要还原 | 较小，主要靠 topojson-client |
| GeoJSON | 大 | 无 | 高，结构直白 | 最广，几乎所有地图库都支持 |
| FlatGeobuf | 小，二进制 | 无 | 低，需工具 | GIS 与部分库 |
| GeoPackage | 中，含索引 | 无 | 低，SQLite | GIS 软件与数据库 |

怎么选不复杂：进网页地图、走第三方接口、需要人眼检查，用 GeoJSON；数据以共享边界为主、体积卡脖子、链路里又已经有 TopoJSON 工具，那就用 TopoJSON。两者互转只改组织方式，不会动坐标系，也不会修掉原本就对不上的边界。

## 转换与工具入口

TopoJSON 与 GeoJSON 互转会改动坐标的数值精度，几何形状本身保持一致；共享边转完之后不保证一位不差。需要互转时用[矢量格式转换](/zh/tools/format-convert/)，GeoJSON 的结构见 [GeoJSON 格式详解](/zh/guide/geojson/)，更多格式对比见 [15 种格式总览](/zh/guide/vector-formats/)。

## 示例数据与解析脚本

- [sample.topojson](/examples/data/sample.topojson)、[topojson_parser.py](/examples/python/topojson_parser.py)

样例里有一个点、一条线和矩形面，`transform` 是 `scale: [0.0001, 0.0001]`、`translate: [-180, -90]`。脚本只依赖标准库，负责还原差值、套用量化参数、按索引把几何拼起来：

```bash
python topojson_parser.py sample.topojson -o out.geojson
```

支持 Point、MultiPoint、LineString、MultiLineString、Polygon、MultiPolygon 与 GeometryCollection，不过对象名不会保留。
