网页地图打开的那一刻，浏览器并不会去下载一张完整的世界地图。它按当前视野，把几十张小图拼起来。这些小图就是**瓦片（tile）**，每张有一个由 `z`、`x`、`y` 组成的编号。把这套编号摸清楚，你就能自己算出一份瓦片清单，离线缓存、服务预热、数据切分都用得上。

## 为什么瓦片是正方形

这一切的前提是 Web 墨卡托投影（EPSG:3857）。地球被它摊到一个正方形平面上：经度固定为 -180°~180°，纬度截到 ±85.0511° 为止。再往极点走，投影后的 y 会趋向无穷，不截断不行。

![墨卡托投影世界地图，高纬度面积被放大](/images/projections/mercator.jpg)

*Web 墨卡托把世界铺成一个正方形，这是瓦片能按正方形切分的原因。图：Strebe，CC BY-SA 3.0，[Wikimedia Commons](https://commons.wikimedia.org/wiki/File:Mercator_projection_SW.jpg)*

投影是正方形，切分才可以用简单的二分：每一级把上一级的每张瓦片切成 4 张。

## z：缩放层级

`z` 是缩放层级，从 0 起算：

- `z=0`：整个世界是 1 张瓦片
- `z=1`：2 × 2 = 4 张
- `z=2`：4 × 4 = 16 张
- 一般规律：每层共 2^z × 2^z 张

![z=0 的单张全球瓦片](/images/guide/osm-tile-z0.png)

*`z=0` 时，整个世界被压进一张 256×256 的瓦片。图：Wikimedia Commons（[文件页](https://commons.wikimedia.org/wiki/File:OSM,_entire_world_map_at_zoom_level_0_in_single_tile.svg)），数据 © OpenStreetMap contributors。*

每加一级，瓦片总数变成 4 倍，地面分辨率翻倍。常见用法是：全国范围 `z=4~8`，城市级 `z=10~14`，街道级 `z=15~18`。

## x 与 y：从哪里开始编号

XYZ 方案规定：**原点在左上角（西北角），x 向东增大，y 向南增大**。数学课本里的直角坐标系 y 轴朝上，这里正好反着来，因为图像坐标本来就从左上角起算。

![z=2 时的瓦片编号，左上角为 0,0](/images/guide/tile-numbering.png)

*`z=2` 时全球分成 4×4 张瓦片：左上角是 `(0,0)`，右下角是 `(3,3)`。图：Wikimedia Commons（[文件页](https://commons.wikimedia.org/wiki/File:Tiled_web_map_numbering.png)），底图 © OpenStreetMap contributors。*

## 经纬度换算成瓦片

设 `z` 层共有 `n = 2^z` 列（行数相同），纬度先转成弧度 `φ`：

```text
x = floor((经度 + 180) / 360 × n)
y = floor((1 − ln(tan φ + 1 / cos φ) / π) / 2 × n)
```

其中 `ln` 是自然对数。纬度超过 ±85.0511° 要先截断，`x`、`y` 再夹取到 `0 ~ n−1`。算出列号和行号，连同层级写成 `z/x/y` 就行了。

例如北京天安门（116.3974°E，39.9088°N）：

| 层级 | x | y | 用途 |
|---|---|---|---|
| `z=10` | 843 | 388 | 城市级 |
| `z=14` | 13489 | 6208 | 街道级 |

同一个点在不同层级编号不同，指的却是同一个位置；`z` 加一级，`x`、`y` 大致翻倍。

## 反过来：瓦片覆盖的经纬度范围

反过来，已知 `z/x/y`，也能算出这张瓦片的四至：

```text
西经 = x / n × 360 − 180
东经 = (x + 1) / n × 360 − 180
北纬 = atan(sinh(π × (1 − 2y / n))) × 180 / π
南纬 = atan(sinh(π × (1 − 2(y + 1) / n))) × 180 / π
```

框选范围、按范围批量下载、把数据按瓦片切块，靠的都是这组反算。

## 一个范围会覆盖多少张瓦片

给定 bbox 和层级区间，把每层覆盖的行列范围相乘，再一层层累加。这个数涨得很快：北京五环范围在 `z=15` 大约几百张，到 `z=18` 就是几万张。所以瓦片清单工具都得设个上限，不然浏览器会先卡死。

## TMS 与 XYZ 的 y 轴差异

TMS（Tile Map Service）叫的也是瓦片，但 y 轴原点放在左下角，y 向上增大。两者的换算是：

```text
y_tms = (2^z − 1) − y_xyz
```

拿到瓦片清单却对不上图，先查是不是 y 轴翻过来了。Google、OpenStreetMap 和大多数网页地图使用 XYZ；部分桌面 GIS 与影像金字塔使用 TMS。

## 常见用途

- **离线地图包**：先列出范围与层级，再按清单下载瓦片。
- **瓦片服务预热**：上线前把热点区域的瓦片生成好，避免首次访问回源。
- **数据切分**：把大批量矢量或影像按瓦片分块并行处理。
- **覆盖范围估算**：评估存储与流量成本。

不过批量抓取瓦片要遵守瓦片服务的使用条款。Google 地图瓦片不允许脱离其 API 单独缓存或再分发。

## 生成自己的 XYZ 清单

手算公式容易出错，跨层级、跨经度范围时尤其明显。用 [Google 瓦片坐标生成](/zh/tools/tile-coords/) 可以在地图上框选区域，或导入 GeoJSON，选好层级后导出 `x, y, z` 的 CSV（Excel 直接能打开），也可以导出每张瓦片一个矩形的 GeoJSON，叠到 QGIS 或地图预览里检查。

## 常见问题

- **为什么 z 加一级瓦片变成 4 倍？** 横竖各切一刀，每张瓦片分成 2×2 四张。
- **为什么纬度要截断在 85.0511°？** Web 墨卡托在这个纬度正好构成正方形，再往极点 y 会发散。
- **瓦片一定是 256 像素吗？** 多数是 256×256，也有 512×512 的高清瓦片；后者在同样的 z 下实际分辨率更高。
- **x/y 从 0 还是 1 开始？** 从 0 开始，`z` 层的最大编号是 `2^z − 1`。

投影本身的类型与选型，见[地图投影类型一览](/zh/guide/projection-types/)；需要把坐标换算成瓦片，用[Google 瓦片坐标生成](/zh/tools/tile-coords/)。
