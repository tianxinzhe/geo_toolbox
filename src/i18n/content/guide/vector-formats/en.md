The same points, lines and polygons can be stored in GeoJSON, KML, GPX, Shapefile, GeoPackage, FlatGeobuf and a dozen other formats. Picking the wrong one rarely fails immediately; the problem appears at delivery, on import, or when someone opens the file in another program.

This page is the overview. Field structures, code samples and conversion traps live on the individual format pages.

## Grouped by format family

| Family | Formats | What it really is | Typical use |
|---|---|---|---|
| JSON | GeoJSON, TopoJSON | Plain text | Web apps, APIs, programmatic use |
| XML | KML, KMZ, GPX, GML | Text / archive | Google Earth, GPS tracks, OGC services |
| Tabular | CSV, TSV, Excel (XLSX/XLS) | Text / archive | Spreadsheet work, batch calculation, reports |
| Text geometry | WKT | Plain text | Databases, logs, a single geometry |
| GIS binary | Shapefile, GeoPackage, FlatGeobuf | File set / SQLite / binary | GIS exchange, large data, mobile |
| CAD and mapping | DXF, GMT, MIF/MID | Text (DXF may be binary) | CAD, GMT plotting, MapInfo |

## Text versus binary

**Text formats** can be opened, diffed in Git and generated by scripts: GeoJSON, TopoJSON, KML, GPX, GML, CSV, TSV, WKT, GMT, MIF/MID and most DXF files.

**Binary or container formats** are smaller and faster but need the right software or library: KMZ (a ZIP archive), Excel (also a ZIP archive), Shapefile (a set of files), GeoPackage (a SQLite database) and FlatGeobuf (a FlatBuffers binary).

A common mistake: KMZ and XLSX look like single formats, but both are ZIP containers. Rename to `.zip`, extract, and you will find XML files inside.

## Quick selection

- **For code or an API**: GeoJSON. Use TopoJSON when size matters and boundaries are shared.
- **For people without GIS software**: KML; add icons and images by packaging it as KMZ.
- **For tracks, waypoints and routes only**: GPX. It cannot express polygons.
- **When Excel is involved**: CSV or TSV. Excel files are for people, not for programmatic exchange.
- **For one geometry**: WKT, for example `POINT (116.3974 39.9088)`.
- **For traditional GIS or industry delivery**: Shapefile, after dealing with field names and layering; prefer GeoPackage when you can choose.
- **For large datasets read quickly**: FlatGeobuf or GeoPackage.
- **For CAD**: DXF. **For GMT plotting**: GMT. **For MapInfo**: MIF/MID.

## Four things conversion tends to lose

1. **Coordinate system declarations**: GeoJSON is WGS84 by specification; Shapefile relies on `.prj`; GeoPackage records the EPSG code in its database. Confirm the source CRS instead of guessing.
2. **Attribute fields**: Shapefile field names max out at 10 characters and one layer holds one geometry type; Excel turns long numerics into scientific notation; CSV without an encoding declaration mangles non-ASCII text.
3. **Geometric detail**: GPX cannot hold polygons; some multi-part polygons do not survive KML; DXF arcs and block references may become polylines.
4. **Styles and attachments**: KML icons, colours and description images disappear when converted to GeoJSON; KMZ attachments need separate handling after extraction.

Conversion itself is not hard. Knowing in advance what will disappear is. To convert files, use the [vector format converter](/en/tools/format-convert/).
