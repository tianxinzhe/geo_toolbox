经纬度是球面上的角度，量不了距离，也算不了面积。工程上要算长度、出图、做规划，绕不开的一步就是把球面“摊平”，这就是投影。

## 投影一定会变形

球面展开成平面，角度、距离、面积不可能同时保住。不同投影的区别，无非是决定保哪一项：

- **等角投影**：局部形状不变形，方向可靠，但面积会随纬度放大。墨卡托属于这一类。
- **等积投影**：面积准确，形状会拉伸。适合统计与制图。
- **等距投影**：只在特定方向上距离准确，适合小范围量测。

所以看到“面积差了几十平方米”，先想想是不是投影用错了，别急着怀疑公式。

## UTM 与高斯克吕格

两者都属于横轴墨卡托，都是分带投影，差别主要在分带方式与比例因子：

| 项目 | UTM | 高斯克吕格 |
|---|---|---|
| 分带宽度 | 6° | 3° 或 6° |
| 中央经线比例因子 | 0.9996 | 1 |
| 假东 | 500,000 m | 500,000 m（带号前缀另计） |
| 常见使用地区 | 全球通用 | 中国等 |

UTM 全球带号统一，跨国数据拼起来方便。高斯克吕格在中国按 3° 带或 6° 带划分，带号与中央经线得跟数据提供方确认。

## EPSG 编码是什么

EPSG 是坐标参考系的编号系统。一个编号背后，基准面、投影方法、单位和参数全都定了。比如：

- `EPSG:4326`：WGS84 经纬度
- `EPSG:3857`：Web 墨卡托，网页地图瓦片使用
- `EPSG:32650`：WGS84 / UTM 50 带
- `EPSG:4547`：CGCS2000 / 3° 高斯克吕格，中央经线 114°E

只写“UTM 50 带”并不够，还得说明基准面是 WGS84 还是 CGCS2000，因为两者的平面坐标会有米级差异。

## 三个容易踩的坑

1. **跨带**：数据横跨两个 3° 带时，不能只用一个带号硬转，边缘变形会明显增大。
2. **轴顺序**：投影坐标按 X=东、Y=北 填写，地理坐标按经度、纬度填写。字段标签必须跟着坐标系走，不能想当然。
3. **单位**：投影坐标的单位是米，经纬度的单位是度。把两者混在一列里计算，结果一定错。

## 怎么选

- 只需要展示、不量测 → 直接用 `EPSG:4326` 或 `EPSG:3857`。
- 做工程量测、面积统计 → 选覆盖范围的投影带，优先等积或局部等距。
- 跨国数据 → UTM；中国国内成果 → 按项目要求选 CGCS2000 的 3° 或 6° 带。

## 常见错误与陷阱

投影与 EPSG 的问题大多不会报错，只会在结果上悄悄偏离。下面四类最常遇到。

1. **把平面坐标当经纬度输入**
   - 现象：在只接受经纬度的输入框里填入 `500000 4331000`，点位落到几内亚湾，或者提示数值超出范围。
   - 原因：源数据是米制投影坐标，列名却写着 lon / lat；从 CAD 图纸或测量成果里复制时，往往不带坐标系信息。
   - 后果：位置偏移上千公里，之后的缓冲、叠加、裁切全部失效，中间步骤不会给出任何警告。
   - 处理：先看量级，经度绝对值不超过 180、纬度不超过 90；超出就说明是平面坐标，查清 EPSG 后再转换。

2. **EPSG:4326 与 EPSG:3857 混用**
   - 现象：底图与叠加图层整体错位，纬度越高偏得越多，量算出的长度也偏大。
   - 原因：两者单位不同，一个度、一个米；Web 墨卡托按投影函数放大坐标，直接当成同一套数值绘制就会偏。
   - 后果：赤道附近不明显，中高纬可能差出几十公里；在 3857 上量面积会被明显放大。
   - 处理：瓦片底图统一用 3857，业务数据存 4326，显示时交给地图库转换，不要在数据里反复改数值。

3. **忽略单位与轴顺序**
   - 现象：坐标对调后图形旋转九十度或镜像，面积结果差了整整一个数量级。
   - 原因：轴顺序与单位由 CRS 定义，例如 EPSG:4326 的官方定义是纬度在前、经度在后，而多数软件按经度、纬度显示。
   - 后果：数值本身合法，几何位置与量算结果却整体错误，排查时容易被误认为公式有问题。
   - 处理：按 EPSG 定义做字段映射，输入输出都注明单位；单位不一致时先换算再计算。

4. **换带与中央经线对不上**
   - 现象：跨带数据拼接处出现拉伸或断裂，整幅图向东、向西偏一个带宽。
   - 原因：只按带号套公式，没有核对中央经线；3° 带与 6° 带编号规则不同，带号前缀也常被省略。
   - 后果：离中央经线越远变形越大，接边处无法对齐，成果不能直接量测。
   - 处理：确认对方用的是 3° 带还是 6° 带、带号是否带前缀，跨带时分区投影后再拼接。

PROJ 字符串与 EPSG 代码，描述的是同一套定义的两个层面。EPSG 代码是注册编号，指向完整的基准、投影、单位与参数；PROJ 字符串把参数逐项写出，例如 `+proj=utm +zone=50 +datum=WGS84`。同一个代码在不同版本的 PROJ 里可能对应更新过的参数，跨软件交换时优先传 EPSG 代码，注册表查不到再退回完整字符串。命令 `projinfo EPSG:4547` 可以列出一个代码实际使用的定义，注册信息见 [epsg.org](https://epsg.org/)，实现与文档见 [proj.org](https://proj.org/)。

## 选型对照

| 场景 | 推荐 CRS | 注意点 |
|---|---|---|
| 网页展示、瓦片底图 | EPSG:3857 | 只用于显示，不在其上量算 |
| 数据入库与交换 | EPSG:4326 | 单位为度，注意经纬度顺序 |
| 中国工程成果 | CGCS2000 的 3° 或 6° 高斯克吕格 | 核对带号、中央经线与假东前缀 |
| 跨国或大范围数据 | WGS84 对应的 UTM 带 | 确认南北半球与带号 |

## 本站工具与示例

不确定一串数值是度还是米，可以先用 [投影坐标转换](/zh/tools/epsg-convert/) 按目标 EPSG 试算，页面会随所选坐标系切换字段标签，避免把东坐标填进纬度。要核对度分秒写法，用 [经纬度格式转换](/zh/tools/dms-decimal/)。处理瓦片时，[Google 瓦片坐标生成](/zh/tools/tile-coords/) 能按框选范围导出 x/y/z 清单，原理见 [Google 地图瓦片原理](/zh/guide/google-tiles/)。转换后的数据要确认落点，用 [地图速览](/zh/tools/map-preview/) 叠加到地图上检查。

各类投影的覆盖范围与适用场景，见[地图投影类型一览](/zh/guide/projection-types/)。需要具体换算时，可以用 [投影坐标转换](/zh/tools/epsg-convert/) 在任意 EPSG 之间转换，页面会按坐标系显示正确的字段顺序。

记住一点：投影不是“选一个能用的就行”，而是要在当前范围内挑一个变形可接受的。选错了不会报错，只会让数字悄悄偏掉。
