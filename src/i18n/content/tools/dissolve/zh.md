## 这个工具解决什么问题

一份地块数据按宗地存储，每条记录都有「用地类型」；一份道路数据按路段存储，每条记录都有「道路等级」。当你只关心类别层面的范围时，需要把同类宗地或同类路段合成一条，否则地图上会出现大量相邻小面与重复边界。桌面 GIS 把这一步叫「按字段融合」或 Dissolve。

本工具读取单个矢量文件，按你选择的字段分组，把同组要素的几何合并，并输出每条结果对应的要素数与几何类型。融合结果可以导出为 GeoJSON，用于制图、面积汇总前的准备，或继续做裁切与缓冲区。

常见场景：把宗地按用地类型融合成用地分布图；把路段按等级融合成路网分级图；把行政区按省份融合成省级边界；把 POI 按类别合并成一个多点图层；把同一批设施的线状记录合并成一条多线。

## 怎么用

第一步，选择矢量文件。支持 GeoJSON、TopoJSON、KML / KMZ、GPX、CSV / TSV、Excel、Shapefile（zip 包）、FlatGeobuf、GeoPackage、WKT、GML、DXF、MIF / MID 与 GMT。GeoPackage 与 Shapefile ZIP 会列出真实图层；GeoJSON 按几何类型拆成点、线、面、其他几个逻辑图层，存在两个以上分组时显示图层下拉框。

第二步，选择融合字段。下拉框列出当前图层出现过的所有属性字段，字段下方会显示最多三个示例值，帮助确认选对了列。字段值会先转成文本并去掉首尾空格再分组；缺失、null 与空串统一归入空组。

第三步，点击融合。结果卡片显示分组数，以及一张「字段值 / 要素数 / 几何类型」的表格，按字段值首次出现的顺序排列。组数超过 2000 时仍会继续计算，但会提示地图绘制与导出可能较慢。组数为 0 时给出空态提示。

地图上的绿色要素是融合结果，蓝色是原始图层，视野会自动缩放到结果范围。

## 类型与结果

- 面要素（Polygon / MultiPolygon）：同组内用 polygon-clipping 做布尔并集，相邻或重叠的面会真正合并边界，结果输出为 MultiPolygon。自相交等非法面会退化为并排保留，至少不丢数据。
- 线要素（LineString / MultiLineString）：同组内所有线拼成一个 MultiLineString，不会自动连接端点或消除悬挂节点。
- 点要素（Point / MultiPoint）：同组内所有点拼成一个 MultiPoint。
- 同组内混合几何：分别处理各类几何后输出 GeometryCollection，例如面并集 + 多点。
- 没有几何的要素仍计入 feature_count，但不会产生几何。
- 每条结果的属性只有融合字段与 feature_count。字段值保留首次出现的原始写法；空组写空字符串。
- 分组顺序按字段值首次出现的位置固定，同一份数据重复融合会得到相同顺序。

## 限制与精度

- 一次最多处理 20 MB、50,000 个要素。组数很多时结果要素也多，建议先筛选或裁剪。
- 面并集只处理二维平面上的经纬度环，不做拓扑修复、不消除悬挂边、不处理自相交以外的复杂错误。极小的缝隙与重叠会按坐标数值判断。
- 线融合不会把首尾相接的路段连成一条，也不会按属性拆分交叉口；需要路网连通性请用专门的网络工具。
- 结果不计算面积。需要面积汇总时，可以导出后按 feature_count 与分类字段再做统计。
- 坐标按 WGS84 经纬度解释，不转换坐标系。投影坐标会显示到错误位置，请先用 EPSG 转换工具处理。
- 所有计算在浏览器本地完成，文件不会上传，也不会写入服务器日志。

## 常见问题

**为什么融合后只有一个要素？** 可能是所选字段在整份数据里只有一个取值，或把字段选成了一列常量。查看字段下方的示例值与结果表，确认分组是否符合预期。

**为什么面融合后还有内部边界？** 布尔并集只消除真正相邻或重叠的边界。若两个面之间有极小的缝隙，坐标不完全一致，或面本身自相交，可能会保留多个部件。可以先用简化或修复工具处理，再重新融合。

**空值组是什么？** 字段缺失、null 与空字符串会被归为同一组，结果表显示「（空）」。这是有意为之，避免空值散落成大量单要素组。

**能一次按两个字段融合吗？** 当前一次一个字段。可以先把两个字段拼成一个辅助字段（例如「类型-等级」），再对这个辅助字段融合。
