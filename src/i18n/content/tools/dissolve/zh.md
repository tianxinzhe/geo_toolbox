## 这个工具解决什么问题

地块数据按宗地存，每条记录都带「用地类型」；道路数据按路段存，每条都带「道路等级」。只关心类别层面的范围时，同类宗地或路段得合成一条，否则地图上满是相邻小面和重复边界。桌面 GIS 里这一步叫「按字段融合」，或者 Dissolve。

本工具读一个矢量文件，按你选的字段分组，把同组要素的几何合起来，输出每条结果的要素数与几何类型。融合结果可以导出 GeoJSON，用于制图、面积汇总前的准备，或接着做裁切与缓冲区。

常见用法：按用地类型把宗地融合成用地分布图；按等级把路段融合成路网分级图；按省份把行政区融合成省级边界；按类别把 POI 并成一个多点图层；把同一批设施的线状记录并成一条多线。

## 怎么用

先选矢量文件。支持 GeoJSON、TopoJSON、KML / KMZ、GPX、CSV / TSV、Excel、Shapefile（zip 包）、FlatGeobuf、GeoPackage、WKT、GML、DXF、MIF / MID 与 GMT。GeoPackage 与 Shapefile ZIP 会列出真实图层；GeoJSON 按几何类型拆成点、线、面、其他几个逻辑图层，分组超过两个时出现图层下拉框。

再选融合字段。下拉框列出当前图层出现过的所有属性字段，字段下方最多带三个示例值，帮着确认列选得对不对。字段值会先转成文本、去掉首尾空格再分组；缺失、null 与空串统一归进空组。

然后点融合。结果卡片给出分组数，还有一张「字段值 / 要素数 / 几何类型」的表，按字段值首次出现的顺序排列。组数超过 2000 时照常计算，但会提示地图绘制与导出可能偏慢。组数为 0 时显示空态提示。

地图上绿色的是融合结果，蓝色是原始图层，视野自动缩放到结果范围。

## 类型与结果

- 面要素（Polygon / MultiPolygon）：组内用 polygon-clipping 做布尔并集，相邻或重叠的面会真正并掉边界，输出 MultiPolygon。自相交这类非法面会退化为并排保留，至少不丢数据。
- 线要素（LineString / MultiLineString）：组内所有线拼成一个 MultiLineString，不会自动接端点，也不消除悬挂节点。
- 点要素（Point / MultiPoint）：组内所有点拼成一个 MultiPoint。
- 同组几何混杂：各类分别处理，最后输出 GeometryCollection，例如面并集加多点。
- 没有几何的要素照样计入 feature_count，但不产生几何。
- 每条结果的属性只有融合字段与 feature_count。字段值保留首次出现的原始写法；空组写空字符串。
- 分组顺序按字段值首次出现的位置固定，同一份数据反复融合，顺序不变。

## 限制与精度

- 单次最多 20 MB、50,000 个要素。组数多，结果要素也多，建议先筛选或裁剪。
- 面并集只管二维平面上的经纬度环，不做拓扑修复，不消除悬挂边，自相交之外的复杂错误也不处理。极小的缝隙与重叠按坐标数值判断。
- 线融合不会把首尾相接的路段连成一条，也不会按属性拆交叉口；要路网连通性请用专门的网络工具。
- 结果不计算面积。需要面积汇总，导出后按 feature_count 与分类字段自己统计。
- 坐标按 WGS84 经纬度解释，不转换坐标系。投影坐标会显示到错误位置，请先用 EPSG 转换工具处理。
- 所有计算在浏览器本地完成，文件不会上传，也不会写入服务器日志。

## 常见问题

**为什么融合后只有一个要素？** 可能是所选字段在整份数据里只有一个取值，也可能字段选成了一列常量。看看字段下方的示例值与结果表，确认分组是否符合预期。

**为什么面融合后还有内部边界？** 布尔并集只消掉真正相邻或重叠的边界。两个面之间有极小缝隙、坐标不完全一致，或者面本身自相交，都可能留下多个部件。可以先用简化或修复工具过一遍，再重新融合。

**空值组是什么？** 字段缺失、null 与空字符串会被归成同一组，结果表显示「（空）」。这是有意为之，免得空值散成一大堆单要素组。

**能一次按两个字段融合吗？** 当前一次一个字段。可以先把两个字段拼成辅助字段（例如「类型-等级」），再按它融合。
