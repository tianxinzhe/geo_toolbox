## 这个工具做什么

有些数据不值得写代码生成，也不值得打开桌面 GIS：勾一个地块、标几个点位、画一条示意路线、圈一个范围。这个工具让你直接在地图上画，画完立即得到可导出的标准矢量数据。

支持五种绘制模式：

- **点**：点击地图落点，连续点击可添加多个独立点。
- **线**：逐点点击，双击或按 Enter 结束，结束前实时显示总长度。
- **面**：逐点点击，双击或按 Enter 闭合，少于三个点时不会生成面。
- **矩形**：从一个角按下并拖到对角。
- **圆**：在圆心按下并拖拽设定半径，按椭球大地线转换为多边形（默认 64 段）。

## 编辑、量测与属性

选择模式下点击要素即可选中。选中后右侧面板用「键 / 值」列出全部属性，可直接改名、改值、删除或新增；属性名不能为空、不能重复，也不能使用 `type`、`coordinates` 等保留字段。

线要素可以拖动顶点调整形状；面要素除了拖动顶点，还能点击边中点插入新顶点。列表中实时显示每个要素的量测值：点显示经纬度，线显示长度，面显示面积与周长。顶部统计栏汇总要素总数、各类型数量、总长度与总面积。

撤销与重做覆盖添加、删除、顶点编辑与属性修改，历史深度 50 步。快捷键：`Ctrl+Z` 撤销、`Ctrl+Y` 重做、`Delete` 删除选中要素、`Esc` 取消当前绘制、`Enter` 结束线/面。

## 导入、导出与坐标系

可以粘贴或选择文件导入 GeoJSON、KML、GPX、CSV、TopoJSON 或 WKT，导入的要素会追加到当前画布，不清空已有内容。导出支持 GeoJSON、KML、GPX、WKT 与 CSV；GPX 无法承载面，遇到面要素时会明确提示跳过的数量。

坐标系固定为 WGS84。所有导出格式都直接写出原始经纬度，不做任何坐标系变换。

## 自动保存与降级

每次要素变更后 1 秒写入浏览器本地存储，重新打开页面会自动恢复并提示恢复数量。存储空间不足时停止自动保存并提示及时导出，不会覆盖已有保存。

底图默认使用免密钥的 OpenStreetMap 街道图，可在右上角切换为 Esri 卫星影像或 Esri 地形图。底图加载失败时绘制、量测与导出仍然可用，只是无法参照地物。要素超过 2,000 个时提示可能影响流畅度，但不阻止继续操作。

## 输入与输出

导入支持粘贴文本或选择文件，格式包括 GeoJSON、KML、GPX、CSV、TopoJSON 与 WKT；新要素追加在原画布之后，已有内容不会被清空。GeoJSON 的 FeatureCollection 按原样展开，CSV 依据经纬度列生成点、其余列作为属性，KML 的几何转成点、线、面，GPX 的航点、航线与轨迹则转成点与线。属性名与值原样保留，大小写不统一也不改。嵌套对象或数组在属性面板里显示成 JSON 文本，直接修改输入框会把它变成字符串；需要保留结构时，应在导入前处理。

输出有六种：GeoJSON、KML、GPX、WKT、CSV 与 Shapefile ZIP。GeoJSON 写成 FeatureCollection，坐标保留 8 位小数，空属性会被移除。CSV 在全部要素都是点时输出 `lng`、`lat` 两列加属性列；只要混入线或面，就改为 `wkt` 列加属性列，这是 CSV 只能承载一种表格结构的必然结果。GPX 不支持面，导出时会跳过并报出数量。Shapefile 以二进制 ZIP 输出，含 `.shp`、`.shx`、`.dbf`、`.prj` 与 `.cpg`，投影声明为 WGS84。圆与矩形都以多边形写出，圆是 64 段近似，半径本身不会自动进入属性，需要保留半径时请手动加一个字段。

## 边界与限制

所有坐标按 WGS84 经纬度处理，不做投影变换。拿到的是投影坐标时，几何会落到错误位置，需要先转换。

绘制过程不做几何合法性校验。折返交叉的自相交面可以被画出并导出，面积按球面公式照常计算，但下游的叠加、缓冲或入库工具可能拒绝这种环，或者给出难以解释的结果。环的方向也没有归一化：GeoJSON 规定外环逆时针、内环顺时针，这里按落点顺序原样写出，多数读取方能够容忍，严格检查绕向的系统则可能要求先修正。坐标顺序与环结构的背景见 [GeoJSON 说明](/zh/guide/geojson/)。

重复点不会自动合并。连续两次点在同一个位置会产生零长度边，长度统计不受影响，导出文件里却会多出重复坐标。清理重复点属于数据修复，不在绘制阶段悄悄执行。

删除、清空与属性修改都可撤销，但撤销栈只有 50 步，更早的状态不可恢复。本地自动保存依赖浏览器配额，配额满时自动保存暂停并提示先导出。底图不可用不影响数据本身。

## 精度与性能

绘制精度最终受屏幕像素限制。缩放到较低层级时，一个像素可能对应几百米甚至更多，落点误差会被直接写进坐标；需要精确位置时应先放大到街道级再落点，或用导入的方式提供已知坐标。圆模式的半径由圆心到按下点的椭球大地线距离决定，不是屏幕上的像素半径，因此换缩放层级不会改变已画好的圆。

长度按逐边大地线累加，面积用等积球上的球面过剩公式计算，两者都不依赖投影平面，高纬度也不会出现面积被横向拉长的经典错误。代价是顶点很多的面要逐边计算，几万个顶点的单个面会让选中和统计明显变慢。要素数量超过 2,000 个时页面已经提示可能影响流畅度；到这个量级，编辑、重绘和导出预览都会变迟钝。

浏览器本地计算适合几个到几百个要素的手工绘制与轻量整理。几千个要素以上的批量编辑、拓扑检查、图层叠加，应换到桌面 GIS 或命令行工具完成，再把结果导回本站查看。

## 一个完整示例

假设要在某个园区标出三个采样点，并圈出以中心点向外 500 米的参考范围。

1. 把底图放大到能看清园区道路，选择点模式，依次点击三个采样位置。每落一个点，列表里立即出现它的经纬度。
2. 切到圆模式，在园区中心按下并向外拖到大约 500 米处松开。画布上出现一个 64 段的多边形，列表里的面积接近该半径对应的球面圆面积。
3. 选中圆，在属性面板新增 `purpose` 键，值填 `survey-area`；再给三个点各加一个 `sample_id`。
4. 导出 GeoJSON，得到一个 FeatureCollection：三个 Point 和一个 Polygon，属性就是刚才填写的键值。若改导出 CSV，因为集合里同时有点和面，CSV 会输出 `wkt` 列而不是 `lng`、`lat` 列。

如果下游只需要点，可以在导出前删掉圆；需要圆的确切半径时，把半径写进属性，因为多边形本身已经不再携带「圆心加半径」这层语义。

## 在中国使用时要注意

底图的坐标基准并不统一。OpenStreetMap 与 Esri 卫星影像使用 WGS84 经纬度（Web Mercator 显示），天地图使用 CGCS2000，两者在实用精度内一致，可以直接对照。高德、腾讯使用 GCJ-02，百度使用 BD-09，与国家大地坐标系之间存在 50~500 米不等、随纬度变化的偏移。把从这些平台复制的坐标直接画到 Esri 卫星图上，点位会明显偏离地物；需要精确落点时，应先把坐标纠偏到 WGS84，或改用天地图影像作参照。

单位方面，工具按米与平方米统计。国内常用的亩与公顷需要换算：1 亩 ≈ 666.67 平方米，1 公顷 = 15 亩 = 10,000 平方米。面积按球面公式计算，适合核对与估算；作为正式测绘成果使用时，仍需具备相应资质与审图号的数据来源，本工具的结果不替代法定测量。
