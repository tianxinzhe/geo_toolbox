## 这个工具解决什么问题

地块、POI、道路这类数据，通常都附着一张属性表：用地类型、行政区名称、人口、面积、状态。想只看其中一类的时候，桌面 GIS 里的操作叫「按属性提取」，数据库里就是一条 WHERE。本工具把这一步收成三件事——选字段、选条件、填值。符合条件的要素直接在地图上高亮，也能导出成新的 GeoJSON。

常见用法有几种：从全市 POI 里取出某一类；筛出面积大于阈值的宗地；只保留某个行政区或某种状态的要素；检查某个字段为空的记录。

## 条件怎么选

- **等于 / 不等于**：字段是数值就按数字比，否则按文本完全匹配。
- **包含**：文本包含，忽略大小写，名称、类型这类字段用得最多。
- **大于 / 大于等于 / 小于 / 小于等于**：按数值比较。字段不是数值时，一个要素都匹配不上，界面会提示。
- **为空 / 不为空**：不用填值，分别对应缺失、null、空字符串，以及其余情况。

字段下拉框最多带 3 个示例值，用来核对是不是选对了字段。条件或字段一改，上一次的结果会自动清空，得重新提取一次。

**选择现有值**：填值框会读取当前字段的全部不同取值（最多 200 个），按数值或文本排序后放进下拉列表。可以直接挑，也能手输一个列表之外的值。

**多图层文件**：GeoPackage 与 Shapefile ZIP 读文件里的真实图层；GeoJSON 没有原生图层，按几何类型拆成点、线、面、其他几个逻辑图层。分组达到两个以上，文件卡片下会出现「图层」下拉框；切到「全部要素」则不拆分。换图层会连带刷新字段、条件与结果。

## 类型与结果

- CSV、Excel 读进来的属性值本质上是字符串。比较之前，工具先看整列能不能都当数字，再决定按数字还是文本比，免得字典序把 "9" 判成大于 "10"。
- 结果保留原始几何与全部属性，要素顺序和源文件一致，导出为 GeoJSON。
- 点怎么去重、面和线怎么显示，交给地图处理；本工具不做几何化简，也不修几何。

## 限制与精度

- 单次上限 20 MB、50,000 个要素，更大的数据请先裁剪。
- 只做单条件筛选。要 AND / OR 组合，可以导出结果后再提取一次。
- 坐标一律按 WGS84 经纬度解释，投影坐标会显示到错误位置，请先用 EPSG 转换工具处理。
- 计算都在浏览器本地跑，文件不上传，也不写入服务器日志。

## 常见问题

**为什么命中了 0 个要素？** 先看字段有没有选对（示例值能帮上忙），再逐字核对值是否和数据一致。「包含」忽略大小写，「等于」要求文本完全相同。数值字段还要确认输入的是数字，不是带单位的文本。

**能按多个字段筛选吗？** 一次只有一个条件。可以先提取一次，导出 GeoJSON，再把它当作输入做第二次提取。

**和裁切工具有什么区别？** 裁切按空间范围筛，这里按属性值筛。两者也能串起来用：先取出某类用地，再用行政区边界裁一刀。

## 输入与输出

输入是一个矢量文件，或者带坐标的表格：GeoJSON、TopoJSON、KML、GPX、CSV、TSV、Excel、Shapefile ZIP、FlatGeobuf、GeoPackage、WKT、GML、DXF、MIF/MID 与 GMT。解析在浏览器里完成，文件不会上传。CSV 与 Excel 的几何来自经纬度列，其余列进属性表；矢量文件的几何与属性原样读入。CSV 的字段名保留表头原样，前后的空格也算进字段名，只有识别经纬度时才对列名宽松一点。

输出是 GeoJSON FeatureCollection，只装命中的要素。几何不动，属性全量复制，要素顺序与源文件一致。筛选过程不改类型：CSV 里的 `"9"` 即使按数值参与了比较，导出时仍然写成字符串 `"9"`，不会被悄悄转成数字。要改字段类型，交给后续的格式转换工具。

字段下拉框列出所有出现过的属性名，最多附三个非空示例值；「选择现有值」最多读 200 个不同取值，排序后供挑选，列表之外也能直接输入。这些都只是辅助，不改变实际的比较规则。

## 空值、大小写与数值

空值包括属性缺失、`null`、空字符串，以及只含空白的字符串。「为空」把这几种都算上；除「为空」「不为空」之外，其他条件遇到空值一律不匹配。字段在某些要素上不存在，也按空值同等对待，不会报错。

文本比较区分大小写，首尾空格也不会自动去掉。「等于」要求字符串完全一致，值前后多一个空格就匹配失败。「包含」不一样：它把字段值和输入都转成小写再做子串判断，输入本身会去掉首尾空格，所以适合名称、类型这类字段。

数值判断按整列来做。整列所有非空值都能解析成数字，这一列才算数值列；中间只要出现一个 `N/A`、带单位的 `12 km`，或者千分位写法 `1,234`，整列就退回文本。数值列上的等于、不等于、大于、小于都按数字走，`9` 与 `9.0` 视为相等，`007` 与 `7` 也相等。整列被判成文本时，界面会提示大小比较不可靠；这时只有单个能解析成数字的值才可能按数值命中，真正含字母的值不会匹配，也不会退化成字典序比较。

布尔值显示成 `true` 或 `false`，按非空文本参与比较。对象与数组显示为 JSON 字符串，包含判断针对这段文本，不适合当作结构化查询。

## 边界与限制

一次只应用一个字段、一个条件。需要 AND 或 OR 时，先提取一次并导出，再把结果交给下一次；两次筛选之间没有藏着什么状态，导出的 GeoJSON 就是全部中间结果。

文件上限是 20 MB 与 50,000 个要素，超了直接拒绝。坐标按 WGS84 经纬度解释；Shapefile 带 `.prj` 时会先转换到 WGS84，其他格式的投影坐标会落到错误位置，得先转换。CSV 按 UTF-8 解码，UTF-8 BOM 会被识别并去掉，GBK 等其他编码读出来是乱码，应先转码。列组织与编码上的坑，见 [CSV 与 TSV 坐标格式详解](/zh/guide/csv-tsv/)。RFC 4180 的引号规则由解析器处理，字段内的逗号、换行和转义引号不会拆错列。

工具不修几何、不去重、也不清理属性。地图上叠在一起的点看起来可能只有一个，数据里照样是多条；真要合并，得用专门工具，或者导出后自己处理。字段名重复、空表头这类问题由解析层按既有规则处理，最好在源文件里先理顺。

## 性能与数据量

加载时要扫一遍属性表，统计字段、示例值和数值特征；之后「选择现有值」会再扫一遍目标字段。这个开销与要素数乘字段数成正比。几万行、几十列的表格，浏览器通常扛得住；几百列再加上很长的值，就会明显变慢。

筛选本身是一次线性遍历，比加载轻。瓶颈往往在解析：大的 GeoJSON 或 Excel 更占内存，接近 50,000 个要素时页面可能卡一下。属性值很长、嵌套对象很多，展示与序列化也会拖慢速度。

所以这个工具适合一次性筛选、检查数据质量、把结果交给下一步。多条件组合、正则、空间条件、分组统计，或者要反复执行的查询，QGIS、空间数据库、脚本更合适。

## 一个完整示例

假设有一份 UTF-8 的 CSV，表头是 `name,category,lng,lat,area_m2`，共 5 行。其中一行 `name` 带英文逗号，用双引号包着；另有一行 `area_m2` 是空的。

先选字段 `category`，条件选「包含」，值填 `park`。大小写与首尾空格都不影响结果，`National Park` 和 `city park` 都会命中。结果表给出命中数量，地图把对应点位高亮出来。

再选字段 `area_m2`，条件选「大于」，值填 `1000`。这一列的非空值都是数字，比较按数值走：`900` 不命中，`12000` 命中；空值那一行对任何「大于」条件都不匹配。想看空值记录，把条件换成「为空」就行。

导出得到只含命中要素的 GeoJSON，`name`、`category`、`area_m2` 都还在，`area_m2` 仍是字符串。要把面积变成真正的数字字段，交给格式转换或后续处理，别在筛选这一步改写源数据。
