## 这个工具解决什么问题

一份地块、POI 或道路数据里通常带属性表：用地类型、行政区名称、人口、面积、状态……想只看其中一类，在桌面 GIS 里是「按属性提取」，在数据库里是一条 WHERE 条件。本工具把这一步做成选字段、选条件、填值三件事，符合条件的要素直接在地图上高亮，并可以导出成新的 GeoJSON。

适合这些场景：从全市 POI 中取出某一类、筛出面积大于阈值的宗地、只保留某个行政区或某种状态的要素、检查某个字段为空的记录。

## 条件怎么选

- **等于 / 不等于**：字段是数值时按数字比较，否则按文本完全匹配。
- **包含**：文本包含，忽略大小写，适合名称、类型这类字段。
- **大于 / 大于等于 / 小于 / 小于等于**：按数值比较。字段不是数值时不会匹配任何要素，界面会提示。
- **为空 / 不为空**：不需要填值，分别匹配缺失、null、空字符串，以及其余情况。

字段下拉框会显示最多 3 个示例值，帮助确认选对了字段。条件或字段改变后，上一次的结果会自动清空，需要重新提取。

**选择现有值**：填值输入框会读取当前字段的全部不同取值（最多 200 个），按数值或文本排序后放进下拉列表，可以直接选，也可以手动输入不在列表里的值。

**多图层文件**：GeoPackage 与 Shapefile ZIP 会读取文件内的真实图层；GeoJSON 没有原生图层，按几何类型拆成点 / 线 / 面 / 其他几个逻辑图层。出现两个以上分组时，文件卡片下会显示「图层」下拉框；切到「全部要素」则不做拆分。切换图层会刷新字段、条件与结果。

## 类型与结果

- CSV、Excel 导入的属性值本质上是字符串；本工具会在比较前判断整列是否都是数字，再决定按数字还是文本比较，避免字典序把 "9" 判成大于 "10"。
- 结果保留原始几何与全部属性，要素顺序与源文件一致，导出为 GeoJSON。
- 点的去重、面与线的显示由地图完成，本工具不做几何化简或修复。

## 限制与精度

- 一次最多处理 20 MB、50,000 个要素；更大的数据请先裁剪。
- 只做单条件筛选；需要 AND / OR 组合时，可以导出结果后再次提取。
- 坐标按 WGS84 经纬度解释，投影坐标会显示到错误位置，请先用 EPSG 转换工具处理。
- 所有计算在浏览器本地完成，文件不会上传，也不会写入服务器日志。

## 常见问题

**为什么命中了 0 个要素？** 先看字段是否选对（示例值能帮忙确认），再检查值是否与数据完全一致；「包含」忽略大小写，但「等于」要求文本完全相同。数值字段请确认输入的是数字而不是带单位的文本。

**能按多个字段筛选吗？** 当前一次一个条件。可以先用一个条件提取，导出 GeoJSON 后再作为输入做第二次提取。

**和裁切工具有什么区别？** 裁切按空间范围筛选，本工具按属性值筛选；两者可以串联，例如先取出某类用地，再用行政区边界裁切。

## 输入与输出

输入是一个矢量文件或带坐标的表格：GeoJSON、TopoJSON、KML、GPX、CSV、TSV、Excel、Shapefile ZIP、FlatGeobuf、GeoPackage、WKT、GML、DXF、MIF/MID 与 GMT。解析在浏览器里完成，文件不会上传。CSV 与 Excel 的几何来自经纬度列，其余列进入属性表；矢量文件的几何与属性原样读入。CSV 的字段名保留表头原样，前后的空格也会成为字段名的一部分，列名匹配只在识别经纬度时做宽松处理。

输出是 GeoJSON FeatureCollection，只包含命中的要素。几何不变，属性全量复制，要素顺序与源文件一致。筛选过程不修改类型：CSV 里的 `"9"` 即使按数值参与比较，导出时仍然写成字符串 `"9"`，不会被悄悄转成数字。需要改变字段类型时，应在后续的格式转换工具里处理。

字段下拉框列出所有出现过的属性名，最多附三个非空示例值；「选择现有值」最多读取 200 个不同取值，排序后供挑选，也可以直接输入列表之外的值。这些只是辅助，不会改变实际比较规则。

## 空值、大小写与数值

空值包括属性缺失、`null`、空字符串，以及只含空白的字符串。「为空」命中这几种情况；除「为空」「不为空」之外，其余条件遇到空值一律不匹配。字段在某些要素上不存在，与空值同等对待，不会报错。

文本比较区分大小写，也不自动去掉首尾空格。「等于」要求字符串完全一致，值前后多一个空格就会匹配失败。「包含」不同：它把字段值和输入都转成小写再做子串判断，输入本身会去掉首尾空格，因此适合名称、类型这类字段。

数值判断是整列级别的。只有该列所有非空值都能解析成数字时，列才被当作数值列；其中出现一个 `N/A`、带单位的 `12 km` 或千分位写法 `1,234`，整列就退回文本。数值列上的等于、不等于、大于、小于都按数字比较，`9` 与 `9.0` 视为相等，`007` 与 `7` 也相等。整列被判为文本时，界面会提示大小比较不可靠；此时只有能解析成数字的单个值才可能按数值命中，真正含字母的值不会匹配，也不会退化成字典序比较。

布尔值会显示成 `true` 或 `false`，按非空文本参与比较。对象与数组显示为 JSON 字符串，包含判断针对这段文本，不适合作为结构化查询。

## 边界与限制

一次只应用一个字段、一个条件。需要 AND 或 OR 时，先提取一次并导出，再把结果作为下一次的输入；两次筛选之间没有隐藏的状态，导出的 GeoJSON 就是全部中间结果。

文件上限是 20 MB 与 50,000 个要素；超过时直接拒绝。坐标按 WGS84 经纬度解释；Shapefile 带 `.prj` 时会先转换到 WGS84，其他格式的投影坐标会落到错误位置，需要先转换。CSV 按 UTF-8 解码，UTF-8 BOM 会被识别并去掉，GBK 等其他编码会变成乱码，应先转码。列组织与编码陷阱见 [CSV 与 TSV 坐标格式详解](/zh/guide/csv-tsv/)。RFC 4180 的引号规则由解析器处理，字段内的逗号、换行与转义引号不会拆错列。

工具不做几何修复、去重或属性清理。地图上重叠的点可能看起来只有一个，数据里仍然是多条；需要去重时，用专门工具或导出后处理。字段名重复、空表头之类的问题由解析层按既有规则处理，最好在源文件里先整理干净。

## 性能与数据量

加载阶段要扫描一遍属性表来统计字段、示例值和数值特征，随后「选择现有值」再扫一遍目标字段。这个成本与要素数乘以字段数成正比；几万行、几十列在浏览器里通常可以接受，几百列且值很长的表格会明显变慢。

筛选本身是单次线性遍历，比加载轻。真正的瓶颈往往是解析：大型 GeoJSON 或 Excel 文件占用内存更多，接近 50,000 个要素时页面可能出现停顿。属性值很长或嵌套对象很多时，展示与序列化也会拖慢速度。

这个工具适合一次性筛选、检查数据质量、把结果交给下一步。需要多条件组合、正则、空间条件、分组统计或反复执行的查询，用 QGIS、空间数据库或脚本更合适。

## 一个完整示例

假设有一份 UTF-8 的 CSV，表头为 `name,category,lng,lat,area_m2`，共 5 行，其中一行 `name` 带英文逗号并用双引号包裹，另有一行 `area_m2` 为空。

先选字段 `category`，条件选「包含」，值填 `park`。大小写与首尾空格不会影响结果，`National Park` 与 `city park` 都会命中。结果表显示命中数量，地图高亮对应点位。

再选字段 `area_m2`，条件选「大于」，值填 `1000`。因为该列的非空值都是数字，比较按数值进行，`900` 不会命中，`12000` 会命中；空值那一行不匹配任何大于条件。若想看空值记录，把条件改成「为空」即可。

导出后得到只含命中要素的 GeoJSON，`name`、`category`、`area_m2` 全部保留，`area_m2` 仍是字符串。需要把面积变成真正的数字字段时，交给格式转换或后续处理，而不是在筛选阶段改写源数据。
