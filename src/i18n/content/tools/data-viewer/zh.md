## 这个工具解决什么问题

手里有一份 GeoJSON、KML、GPX 或者从别的系统导出的 Excel 坐标表，想先确认「它在实地到底落在哪」，通常要装桌面 GIS 或者把它导入在线服务。这个工具把这一步做成一件事：选文件，看地图。

数据只在浏览器里读一次，解析成统一的 GeoJSON 后交给地图绘制，不需要注册、不需要上传，也不用担心中间服务留存你的业务数据。适合核对数据是否翻了 Y 轴、是否偏到了隔壁城市、边界有没有闭合。

## 支持的格式

| 格式 | 常见扩展名 | 说明 |
| --- | --- | --- |
| GeoJSON / TopoJSON | `.geojson` `.json` `.topojson` | 直接显示，无需转换 |
| KML / KMZ | `.kml` `.kmz` | Google Earth 导出；KMZ 是压缩包，按字节解析 |
| GPX | `.gpx` | 轨迹点、路线与航点 |
| CSV / TSV | `.csv` `.tsv` `.txt` | 需要经度、纬度两列，列名可自动识别 |
| Excel | `.xlsx` `.xls` | 读取第一个工作表的坐标列 |
| Shapefile | `.zip` | 需把 `.shp`/`.dbf`/`.prj` 等打包成 zip |
| FlatGeobuf / GeoPackage | `.fgb` `.gpkg` | 二进制矢量格式，按图层读取 |
| WKT / GML | `.wkt` `.gml` | 文本几何与 OGC 交换格式 |
| DXF / MIF / MID / GMT | `.dxf` `.mif` `.mid` `.gmt` | 常见 CAD 与桌面 GIS 交换格式 |

Leaflet 本身只支持 GeoJSON，上表里除 GeoJSON 以外的格式，都会先在本页内用 JavaScript 解析、转成 GeoJSON 再绘制，所以你不需要先跑一趟格式转换。

## 自动识别与手动指定

选择文件后，工具先看内容特征（JSON 结构、XML 根元素、CSV 表头等）再结合扩展名判断格式。多数情况下直接就能显示。

如果内容特征不足以判断——例如没有扩展名、文件被改过名、或者是一段没有表头的坐标文本——页面会明确提示「无法识别文件格式」。这时在左侧「文件格式」下拉框里选中正确的格式，工具会立刻用你指定的格式重新解析，不需要重新选文件。

格式选错时通常会得到两种结果：解析报错，或者坐标超出经纬度范围。后者往往说明文件里是投影坐标而不是经纬度。

## 地图上怎么显示

解析结果会统一成 GeoJSON，然后：

- 点、线、面都按原始几何绘制，保留原有环与洞；
- 自动缩放到数据的包围范围，方便一眼看到整体分布；
- 左侧给出格式、要素数量、几何类型分布与解析问题条数；
- 数据为空或坐标全部非法时，地图保持默认视野并给出提示，而不是显示一张空白地图。

底图可以切换街道、影像与地形；底图瓦片加载失败只影响背景，不影响你的数据。需要继续编辑或导出时，可以把同一份数据交给[地图绘制工具](/zh/tools/map-draw/)，或者用[矢量格式转换](/zh/tools/format-convert/)另存为其他格式。

## 限制与精度

- 单个文件上限 20 MB，要素上限 50,000 个；超过时请先裁剪范围或简化几何。
- 坐标按 WGS84 经纬度解释，不读取 `.prj` 里声明的投影，也不做基准面转换。投影坐标请先用 [EPSG 坐标转换](/zh/tools/epsg-convert/) 处理。
- Shapefile 必须打包成 zip 上传，单独的 `.shp` 缺少属性与投影信息。
- Excel 只读第一个工作表，多表工作簿请先拆成单表文件。
- 所有计算在浏览器内完成，页面不请求任何计算接口，也不会把数据写入本地存储。

## 常见问题

**数据会上传到服务器吗？** 不会。文件通过 File API 读取，解析与绘制都在本页完成；刷新页面后数据即消失。

**支持哪些格式？** 上表列出的 14 类格式都可以；除 GeoJSON 外都会先在本地转成 GeoJSON 再显示。

**为什么数据位置偏了？** 多半是文件里存的是投影坐标（米），而工具按 WGS84 经纬度解释。请先用 EPSG 坐标转换工具转成经纬度再查看。
