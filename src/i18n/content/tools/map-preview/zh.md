## 这个工具解决什么问题

手里有一份 GeoJSON、KML、GPX，或者从别的系统导出的 Excel 坐标表，想先确认「它在实地到底落在哪」。通常得装桌面 GIS，或者把数据导进某个在线服务。这一步在这里被压成两件事：选文件，看地图。

数据只在浏览器里读一次，解析成统一的 GeoJSON 再交给地图。不用注册，不用上传，也不用担心中间服务把你的业务数据留下来。核对数据翻了 Y 轴没有、是不是偏到了隔壁城市、边界闭没闭合，都适合用它。

## 支持的格式

| 格式 | 常见扩展名 | 说明 |
| --- | --- | --- |
| GeoJSON / TopoJSON | `.geojson` `.json` `.topojson` | 直接显示，无需转换 |
| KML / KMZ | `.kml` `.kmz` | Google Earth 导出；KMZ 是压缩包，按字节解析 |
| GPX | `.gpx` | 轨迹点、路线与航点 |
| CSV / TSV | `.csv` `.tsv` `.txt` | 需要经度、纬度两列，列名可自动识别 |
| Excel | `.xlsx` `.xls` | 读取第一个工作表的坐标列 |
| Shapefile | `.zip` | 需把 `.shp`/`.dbf`/`.prj` 等打包成 zip |
| FlatGeobuf / GeoPackage | `.fgb` `.gpkg` | 二进制矢量格式，按图层读取 |
| WKT / GML | `.wkt` `.gml` | 文本几何与 OGC 交换格式 |
| DXF / MIF / MID / GMT | `.dxf` `.mif` `.mid` `.gmt` | 常见 CAD 与桌面 GIS 交换格式 |

Leaflet 本身只认 GeoJSON。表里除了 GeoJSON，其他格式都会先在本页用 JavaScript 解析、转成 GeoJSON 再画，所以不必先跑一趟格式转换。

## 自动识别与手动指定

选好文件，工具先读内容特征——JSON 结构、XML 根元素、CSV 表头——再结合扩展名判断格式。多数情况下选完就能看到结果。

有些文件光看内容不够：没有扩展名、改过名，或者只是一段没表头的坐标文本。这时页面会直接说「无法识别文件格式」。到左侧「文件格式」下拉框里挑正确的格式，工具立刻按你指定的格式重新解析，文件不用重选。

格式选错，一般会撞上两种结果：要么解析报错，要么坐标超出经纬度范围。后者多半说明文件里存的是投影坐标，而不是经纬度。

## 多个文件叠加

一次选多个文件可以，分几次添加也可以。每个文件各自解析、各自统计，卡片上标着格式和要素数量；点卡片右上角的「×」就把它删掉，其他文件不受影响。

解析成功的文件会合并叠加到同一张地图，视野自动缩放到全部数据的范围。左侧顶部汇总当前文件数与要素总数，「清除数据」一次清空所有文件。

## 地图上怎么显示

不管什么格式，解析结果最后都是 GeoJSON，然后：

- 点、线、面按原始几何绘制，原有的环与洞保留；
- 自动缩放到数据的包围范围，整体分布一眼能看到；
- 每个文件给出格式、要素数量、几何类型分布和解析问题条数；
- 数据为空或坐标全部非法时，地图停在默认视野并给出提示，不会甩给你一张空白图。

底图可以切街道、影像与地形；瓦片加载失败只影响背景，你的数据照旧。想接着编辑或导出，把同一份数据交给[地图绘制工具](/zh/tools/map-draw/)，或者用[矢量格式转换](/zh/tools/format-convert/)另存成别的格式。

## 限制与精度

- 单个文件上限 20 MB，要素上限 50,000 个；超了请先裁剪范围或简化几何。
- 坐标按 WGS84 经纬度解释，不读 `.prj` 里声明的投影，也不做基准面转换。投影坐标请先用 [EPSG 坐标转换](/zh/tools/epsg-convert/) 处理。
- Shapefile 必须打成 zip 再上传，光给一个 `.shp` 缺少属性与投影信息。
- Excel 只读第一个工作表，多表工作簿请先拆成单表文件。
- 所有计算都在浏览器内完成，页面不请求任何计算接口，也不会把数据写进本地存储。

## 常见问题

**数据会上传到服务器吗？** 不会。文件通过 File API 读取，解析与绘制都在本页完成；刷新页面后数据即消失。

**支持哪些格式？** 上表列出的 14 类格式都可以；除 GeoJSON 外都会先在本地转成 GeoJSON 再显示。

**为什么数据位置偏了？** 多半是文件里存的是投影坐标（米），而工具按 WGS84 经纬度解释。请先用 EPSG 坐标转换工具转成经纬度再查看。
