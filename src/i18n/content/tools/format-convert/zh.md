## 这个工具解决什么问题

同一份地理数据，在不同软件里往往要求不同的文件格式：GIS 桌面端偏好 GeoJSON 或 TopoJSON，Google Earth 要 KML/KMZ，GPS 设备与运动应用要 GPX，数据分析与报表要 CSV，数据库与开发联调又常用 WKT；大体量数据交换与 GIS 数据库之间，则越来越常用 FlatGeobuf 与 GeoPackage。格式转换本身不难，难的是找到不需要注册、不需要上传、还能把属性与几何都保留下来的工具。

本工具把整条链路放在浏览器里：选择源格式与目标格式 → 读取 → 解析 → 摘要与校验 → 预览 → 下载。文件不会离开你的设备。

## 支持的格式

输入支持 GeoJSON、KML、KMZ、GPX、CSV/TSV、Excel（XLSX/XLS）、GML、DXF、GMT、MIF/MID、TopoJSON、WKT、FlatGeobuf（FGB）与 GeoPackage（GPKG），以及打包为 ZIP 的 Shapefile（`.shp/.dbf/.shx/.prj`）。输出支持 GeoJSON、KML、KMZ、GPX、CSV、XLSX、GML、DXF、GMT、MIF/MID、TopoJSON、WKT、FlatGeobuf、GeoPackage 与 Shapefile ZIP。输入与输出为同一格式时也允许提交，此时行为等同「格式化 + 校验」，结果区会明确说明。

各格式的边界需要提前知道：Excel 读取第一个工作表，经纬度列规则与 CSV 相同；GML 覆盖常见的简单要素（Point/LineString/Polygon 及其 Multi 形式），复杂应用模式不展开；DXF 只处理 ASCII 二维实体（POINT、LINE、LWPOLYLINE、POLYLINE、CIRCLE、ARC），不携带属性，且 CAD 坐标不声明地理坐标系；GMT 为纯文本约定，多边形内环无法表达；MIF/MID 输出会打包成包含 `data.mif` 与 `data.mid` 的 ZIP；读取这种 ZIP 时请把源格式显式选为 MIF/MID，否则 `.zip` 会按 Shapefile 处理。遇到这些情况会在结果区给出警告，而不是静默丢弃。

页面顶部可以分别选择「源格式」和「目标格式」，两者互相独立。源格式默认是「自动识别」，按文件扩展名和内容判断；也可以手动指定。当同一段文本存在两种合理解释时——例如纯逗号分隔的内容既像 CSV 又像坐标列表、`.json` 既可能是 GeoJSON 也可能是 TopoJSON、XML 头难以区分 KML 与 GPX——手动指定源格式可以避免误判。指定之后工具会严格按所选格式解析，不会在失败时偷偷回退到自动识别，这样错误才会暴露出来。目标格式决定输出，切换它不会重新解析输入。

Shapefile 需要先把 `.shp`、`.dbf`、`.shx` 与 `.prj` 一起打包成 ZIP 再上传，一次只读取第一个图层。ZIP 内若带 `.prj`，工具会按其声明的坐标系把坐标重投影到 WGS84；没有 `.prj` 时按 WGS84 原样处理，并在摘要区提示。

导出 Shapefile 时生成一个 ZIP，内含 `.shp/.shx/.dbf/.prj/.cpg`，坐标统一为 WGS84，属性以 UTF-8 写入 DBF。由于一个 Shapefile 图层只能容纳一种几何类型，点、线、面混合时会被拆成多个图层；DBF 字段名受 10 个字符限制，超长或含非 ASCII 字符时会自动重命名并在结果区提示。Shapefile 是二进制格式，页面内不提供文本预览，下载后可直接用 QGIS 或 ArcGIS 打开。

FlatGeobuf（`.fgb`）与 GeoPackage（`.gpkg`）同样是二进制格式，只在浏览器里按需加载解码器，页面内不提供预览。两者都按单图层处理：FGB 把输入要素写成一个集合；GPKG 只读取第一个要素图层，并在结果区提示其余图层数量。导出 GPKG 时会生成一个 SQLite 数据库，表名为 `features`，几何列名为 `geom`，坐标系固定为 EPSG:4326；属性列类型跨要素推断，数字与布尔混用或出现嵌套对象时降级为文本，对象与数组会转成 JSON 字符串。FGB 的列结构由首条要素推断，工具会先对齐所有要素的属性列，类型不一致时统一为文本并给出警告。两者都会保留全部要素，空几何写入 NULL 并计入警告，不会静默丢行。

CSV/TSV 会自动识别常见的经纬度列名，例如 `lat/lng`、`latitude/longitude`、`纬度/经度`、`y/x`。识别不到时不会猜列，而是列出表头让你手动选择。文件编码默认按 UTF-8 读取；遇到旧版中文数据可以切换到 GBK / GB18030 重试。

## 属性、几何与降级

默认保留全部属性。当目标格式能力有限时，工具提供明确的降级选项：GPX 只能承载 name 与 description，你可以选择「保留 name 与 desc，其余属性合并进描述」或「仅保留 name」。

目标格式不支持某类几何时，工具不会静默丢弃：例如 GeoJSON 的面数据转 GPX，会先列出受影响的要素数量与类型，让你选择跳过或换格式。空几何、坐标超出经纬度范围、多边形环未闭合等问题会被收集到「问题清单」，但不阻断转换——你可以先完成转换，再回头处理数据质量。

## 坐标、取整与预览

转换过程不做坐标系变换。这一点在摘要区有常驻警告：如果数据不是 WGS84，位置可能偏移，应先用坐标系或投影转换工具处理。

高级选项提供三个开关：缩进美化 / 压缩单行、坐标小数位截断（0~12，默认 7 位）、移除空属性。预览只渲染前 200 行文本，下载的是完整结果；要素结构树只展示前 20 条，避免大文件拖慢页面。

## 限额与隐私

单个文件上限 20 MB，最多 50,000 个要素；粘贴文本上限 200,000 字符。超限时会明确告知实际数值与限额，不会尝试处理。文件仅在当前标签页内存中存在，不上传、不写入本地存储，关闭页面即销毁。

## 国内数据源与中文编码

国内公开数据多以 Shapefile（CGCS2000）或 GDB 分发，GeoJSON 相对少见。GDB 不是本工具的输入格式，需要先在 QGIS 或 ArcGIS 里导出为 Shapefile 或 GeoPackage。Shapefile 若带有 `.prj`，导入时会按其声明转换到 WGS84；CGCS2000 与 WGS84 的差异在厘米级，坐标数值几乎不变。

高德、腾讯开放平台返回 GCJ-02 坐标，百度返回 BD-09。把接口结果存成 CSV 再转成 GeoJSON，只是换了容器，偏移仍然存在：这些坐标与 WGS84 相差 50~500 米，放到 OSM 或天地图底图上会整体错位。需要与卫星影像对齐时，先做纠偏，再进入本工具。

编码是另一个常见问题。Excel 另存为 CSV 时默认使用本地编码，中文 Windows 下通常是 GB18030；工具在 CSV/TSV 的导入选项里提供 UTF-8 与 GBK/GB18030 两种选择，选错时属性里的中文会变成乱码，坐标列不受影响。Shapefile 的属性由 DBF 承载，带 `.cpg` 且声明 UTF-8 时中文正常，缺少 `.cpg` 的旧数据按 GBK 读取。DBF 字段名上限为 10 个字符，较长的中文名会在导出时被重命名并提示。
