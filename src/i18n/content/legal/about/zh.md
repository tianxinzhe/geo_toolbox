## 这个站是做什么的

地理工具箱是一组**在线地理信息小工具**的集合。当前 15 个工具覆盖四类高频需求：

- **坐标与转换**——度分秒与十进制度互转、按 EPSG 代码做投影坐标转换
- **数据格式**——GeoJSON / KML / KMZ / GPX / TopoJSON 互转、WKT 与 GeoJSON 互转、MVT 矢量瓦片解析
- **空间编码**——把坐标压缩成 GeoHash 短字符串，或编码成 Plus Code，便于索引、分享与口述
- **地图与可视化**——在线绘制点线面并导出、生成等距圈与缓冲区、查看本地矢量数据、裁切与叠加图层、按属性提取要素、导出 XYZ 瓦片坐标

每个工具都是一个独立页面，配有说明文档，解释这个工具解决什么问题、结果应该怎么读、精度边界在哪里。

## 为什么做成这样

做这个站的起因是三个反复出现的具体时刻。

**第一个是坐标系错配。** 把投影平面坐标（七位数的 X/Y）当成经纬度直接投到底图上，点位会整体错位，甚至落到海里。这个错误在联调阶段很难一眼看出来——点还在地图上，只是不在正确的位置。等意识到是坐标基准或投影问题时，往往已经排查了半天。

**第二个是找不到可信的格式转换工具。** 拿到一份 KML 要转 GeoJSON，或者一份带经纬度列的表格要转成矢量数据，搜索到的在线工具大多要求注册、要求把文件上传到服务器，或者界面陈旧、结果无法验证。

**第三个是数据隐私顾虑。** 地块边界、门店位置、轨迹数据往往属于商业敏感信息。把它粘贴到一个不知名的第三方网站，需要相当的信任——而这种信任很难建立。

所以本站的三个核心决策是：

| 决策 | 理由 |
|---|---|
| **纯静态部署，无后台服务** | 站点在架构上不具备接收用户数据的能力。"数据不出浏览器"不是一句承诺，而是可以自行验证的事实 |
| **每个工具独立成页并配文档** | 让你从搜索引擎直达需要的那个工具，而不是先 landing 再翻菜单找 |
| **不用需要密钥的商业地图或地理编码服务** | 密钥在无后台环境下无法保管，暴露即被盗刷。因此第一期不含路径规划、等时圈与商业级地址解析 |

## 技术上怎么实现的

站点用 [Astro](https://astro.build/) 构建为纯静态页面，部署在 Cloudflare Pages 上。交互部分用 Vue 3 的岛屿架构——只有真正需要交互的组件才加载 JavaScript，其余部分是纯 HTML 与 CSS。

计算相关的依赖按工具页面切分：地图用 Leaflet（约 42KB gzip，仅在需要地图的 8 个工具页加载，且采用懒加载）；投影引擎用 proj4 配合按需注册的投影定义；Vincenty 大地测量算法用 geodesy 库；GeoHash 编解码与 WKT 解析器为自研，因为这几个场景需要对实现细节有完全的控制权。

设计上刻意保持克制：白底、单一强调色、1px 边框分隔、数值等宽对齐、零阴影、零装饰。这套风格不是审美偏好，而是四个目标同时指向的结果——Core Web Vitals 达标要求零阻塞资源，广告与内容的清晰边界要求不用阴影，爬虫友好要求语义化 HTML，页面简洁本身就是产品要求。

## 内容如何维护

工具的计算逻辑有单元测试覆盖，投影转换等关键部分使用实算的参考值作为黄金用例，任何改动都会与这些参考值比对。文档区的算法说明与参考数值在实现变更时同步更新。

如果你发现某个工具的结果与你已知的正确值不符，或者文档里有事实性错误，请通过[联系方式页面](/zh/contact/)告诉我们。**计算错误是本站最严重的问题类型**，会优先处理。

## 这个站不适合做什么

说清楚边界同样重要：

- **法定用途的测绘成果**——国土调查、地籍测量、工程放样必须使用具备资质的工具与流程，本站结果不构成法定依据。详见[免责声明](/zh/disclaimer/)
- **大规模服务端批处理**——没有后台，处理规模受你设备的内存限制。数万行的 CSV 可以在浏览器里处理，数千万行不行
- **路径规划、等时圈、地址解析**——这些依赖需要密钥的商业服务，与"无后台"的架构约束冲突，第一期不做
- **协作与版本管理**——没有账号系统，就不存在多人协作。分享只能通过 URL 参数
